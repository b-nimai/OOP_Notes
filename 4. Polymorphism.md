# Polymorphism

> **One-liner:** "Many forms" — one entity (method/object) behaves differently by context. Two flavors: **compile-time** (overloading) and **run-time** (overriding).

**Trigger phrase:** *"same call, different behavior by context — resolved by argument types at compile-time (overload) or by actual object type at run-time (override)."*

---

## Core Idea
One name, many behaviors. The split is **when the method is resolved**:
| | **Compile-Time (Static)** | **Run-Time (Dynamic)** |
|---|---|---|
| Achieved by | **Method overloading** | **Method overriding** |
| Resolved | At **compile time** (by signature) | At **run time** (by actual object) |
| Mechanism | Static binding (early) | Dynamic method dispatch (late) |
| Speed | Faster (early binding) | Slower (late binding) |
| Needs inheritance | No | **Yes** |

## 1. Compile-Time — Method Overloading
Same method name, **different parameter list** (count/type/order); compiler picks the match from the **argument types**.
```java
class Calculator {
    int    add(int a, int b)       { return a + b; }   // picked for add(5, 3)
    double add(double a, double b) { return a + b; }   // picked for add(5.5, 3.3)
}
```
- ⚠️ **Return type alone can't overload** — signature differs only by params.
- Operator overloading is another form, but **Java doesn't support it** (C++ does).

## 2. Run-Time — Method Overriding
Subclass redefines a parent method; the **JVM dispatches on the actual object type, not the reference type**.
```java
class Animal { void sound(){ System.out.println("Animal makes a sound"); } }
class Dog extends Animal {
    @Override void sound(){ System.out.println("Dog barks"); }
}

Animal a = new Dog();   // reference Animal, object Dog
a.sound();              // "Dog barks" — decided at RUNTIME by object type
```
This is the payoff of [[3. Inheritance]] + overriding: program to the parent type, get subclass behavior automatically.

## Key Takeaways
1. **Overloading = compile-time** (signature), **Overriding = run-time** (object type). Memorize this pairing.
2. **Reference type vs object type:** `Animal a = new Dog()` → overridden call follows **Dog** (the object), not Animal (the reference).
3. Return type **cannot** distinguish overloads.

## Pitfalls
- **Overloading ≠ overriding.** Different params + same class = overload (static); same params + parent/child = override (dynamic). → table in [[3. Inheritance]].
- **Late binding only applies to overridden instance methods.** `static`, `final`, and `private` methods are bound at compile time (no dynamic dispatch).
- **C++ contrast:** dynamic dispatch in C++ needs the `virtual` keyword; in Java every non-`final`/non-`static` method is virtual by default. And Java has **no operator overloading**.
