# Static Keyword

> **One-liner:** `static` binds a member to the **class itself**, not to any instance — one copy in memory, shared by every object, usable without `new`.

**Trigger phrase:** *"belongs to the class, not the object — loaded once when the class loads; static methods/vars need no instance and can't touch non-static state directly."*

---

## Core Idea
`static` marks a member as belonging to the **class** rather than to a specific instance. It applies to **variables, methods, blocks, and nested classes**. A static member is loaded **once** during the class's lifecycle and is **shared across all instances**.

## Static Variables (class variables)
One copy, shared by every object; initialized **once** when the class loads. Ideal for shared counters or constants.
```java
class Counter {
    static int count = 0;          // static variable — shared by all objects

    Counter() { count++; }         // every construction bumps the same copy

    static void displayCount() { System.out.println("Count: " + count); }
}

class Main {
    public static void main(String[] args) {
        Counter c1 = new Counter();
        Counter c2 = new Counter();
        Counter.displayCount();    // Count: 2  (one shared count, not 0)
    }
}
```
`count` is shared across all `Counter` objects → the output is **2**, not 0.

## Static Methods
Belong to the class; callable **without an object**. Used for utility / helper functions (e.g. math).
```java
class MathUtils {
    static int add(int a, int b) { return a + b; }
}

class Main {
    public static void main(String[] args) {
        int result = MathUtils.add(5, 3);   // no instance needed
        System.out.println("Result: " + result); // Result: 8
    }
}
```
**Keypoints**
- A static method **cannot access non-static members directly** — those need an instance.
- A static method can only directly call **other static methods** and access **static variables**.

## Static Blocks (static initialization blocks)
Used to initialize static variables. Run **when the class loads** — before any object is created or any static method is called. Multiple blocks execute **top-to-bottom** in declaration order.
```java
class Example {
    static int value;

    static {                       // runs once, at class load
        value = 10;
        System.out.println("Static block executed.");
    }
}

class Main {
    public static void main(String[] args) {
        System.out.println("Value: " + Example.value);
        // Static block executed.
        // Value: 10
    }
}
```

## Static ↔ Non-Static interaction
A static method can't reach instance members directly (no `this`), but it **can** by creating an instance:
```java
class Example {
    int instanceVar = 10;

    static void staticMethod() {
        Example obj = new Example();   // make an instance to reach non-static state
        System.out.println("Instance variable: " + obj.instanceVar);
    }
}

class Main {
    public static void main(String[] args) { Example.staticMethod(); }
}
```

## Advantages
- **Memory efficiency** — static variables are loaded once, cutting memory use.
- **Utility functions** — static methods suit object-independent helpers (e.g. `Math.sqrt()`).
- **Initialization** — static blocks prep shared resources before any use.
```java
class Utils {
    static void printMessage(String message) { System.out.println(message); }
}
class Main {
    public static void main(String[] args) {
        Utils.printMessage("Hello, Static!"); // Hello, Static!
    }
}
```

## Interview Q&A (memorize)
1. **Why can't a static method use non-static members directly?** Static members exist without any instance; non-static members need a specific object (`this`). No instance → nothing to resolve `instanceVar`/instance methods against.
2. **When does a static variable get initialized?** Once, when the class is **loaded** into memory — before objects exist.
3. **Static block vs constructor?** Static block runs **once at class load**; a constructor runs **every time** an object is created.

## Pitfalls
- **Shared state surprises.** A static variable is one copy for the whole class — mutating it from one object is visible to all (the `count: 2` effect).
- **`static` ≠ `final`.** Static means *class-level*; it's still mutable unless also `final`. `static final` = a true constant.
- **Don't overuse static.** Static methods/state break instance-based design and make code harder to test/mock — reach for it only for genuinely shared data or stateless helpers.
- **Calling a static method on an instance compiles but misleads.** `c1.displayCount()` works yet hides that it's class-level — always qualify with the **class name**.
