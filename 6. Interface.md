# Interface

> **One-liner:** A pure **contract** — a list of *what* a class must do, with no *how*. A class that `implements` it promises to provide a body for every method.

**Trigger phrase:** *"a 100% abstract blueprint — abstract methods + constant fields only; a class signs the contract with `implements` and must fulfil every method; one class can sign many (→ multiple inheritance)."*

---

## Core Idea
An interface declares a set of **abstract methods** (no body) that any implementing class must define. It specifies the *behaviour* without dictating the *implementation* — the cleanest form of [[5. Abstraction]].

```java
interface Animal {
    void eat();
    void sleep();
}

class Dog implements Animal {
    @Override public void eat()   { System.out.println("Dog eats bones."); }
    @Override public void sleep() { System.out.println("Dog sleeps in a kennel."); }
}
```
`Animal` = the contract; `Dog` = an implementer supplying concrete behaviour for both methods.

## What an interface can / can't have
| | Interface |
|---|---|
| **Instance variables** | ❌ No. Every field is implicitly **`public static final`** → constants, not state. A non-static/non-final field won't compile. |
| **Constructor** | ❌ No. It has no state to initialise and can't be instantiated. (The *implementing class* still has its own constructors.) |
| **Methods** | abstract (implicitly `public abstract`) + `default` / `static` (Java 8+) + `private` (Java 9+). |
| **Multiple inheritance** | ✔️ A class can `implements` **many** interfaces → Java's safe substitute for multiple class inheritance. |

```java
interface Vehicle { void start(); }

class Car implements Vehicle {
    private String brand;
    Car(String brand) { this.brand = brand; }     // class has a constructor; interface does not
    @Override public void start() { System.out.println(brand + " car is starting."); }
}
```

## Multiple interfaces (dodging the Diamond)
Java forbids `extends` of multiple classes (Diamond ambiguity — see [[3. Inheritance]]) but allows implementing many interfaces:
```java
interface Flyable   { void fly();  }
interface Swimmable { void swim(); }

class Duck implements Flyable, Swimmable {
    @Override public void fly()  { System.out.println("Duck is flying."); }
    @Override public void swim() { System.out.println("Duck is swimming."); }
}
```

## Why interfaces matter
- **Multiple inheritance of type** — combine capabilities from several sources.
- **Contract** — guarantees consistency: every implementer exposes the same API.
- **Loose coupling** — program to the interface, not the concrete class, so implementations are swappable.

```java
interface PaymentGateway { void processPayment(double amount); }

class PayPal implements PaymentGateway {
    @Override public void processPayment(double amount) {
        System.out.println("Processing payment via PayPal: $" + amount);
    }
}
class Stripe implements PaymentGateway {
    @Override public void processPayment(double amount) {
        System.out.println("Processing payment via Stripe: $" + amount);
    }
}
```
A client uses any `PaymentGateway` without being tied to PayPal *or* Stripe → [[4. Polymorphism]] in action.

## `default` and `static` methods (Java 8+)
- **`static` method** — belongs to the *interface itself*; call it as `Example.staticMethod()` without any instance. Can only touch other **static** members of the interface, never instance state of implementers.
  ```java
  interface Example { static void hi() { System.out.println("static method in an interface."); } }
  // Example.hi();
  ```
- **`default` method** — has a **body** in the interface (the `default` keyword). Callable on any implementing object; an implementer may override it.
  ```java
  interface Example { default void greet() { System.out.println("This is a default method."); } }
  ```

**Why `default` was added:** before Java 8, adding a method to an interface **broke every existing implementer**. `default` methods let libraries/APIs evolve while old classes keep compiling (backward compatibility). They also help resolve clashes when a class implements multiple interfaces with the same signature.

## Interface inheritance
An interface can `extends` another (even several), growing the contract:
```java
interface Animal { void eat(); }
interface Mammal extends Animal { void walk(); }   // inherits eat(), adds walk()

class Human implements Mammal {
    @Override public void eat()  { System.out.println("Human eats food."); }
    @Override public void walk() { System.out.println("Human walks on two legs."); }
}
```
`Human` must implement **both** the inherited `eat()` and the new `walk()`.

## Interview Q&A (memorize)
1. **Can an interface have instance variables?** No — all fields are `public static final` constants.
2. **Can an interface have a constructor?** No — no state, can't be instantiated. The implementing class can.
3. **Can a class implement multiple interfaces?** Yes — Java's answer to multiple inheritance.
4. **Interface vs abstract class?** See [[5. Abstraction]]: interface = pure capability/contract, multiple inheritance, constants only; abstract class = shared base + shared code, single `extends`, instance fields + constructor.

## Pitfalls
- **Fields are silently constants.** Anything declared in an interface is `public static final` — never instance state.
- **No constructor, no instantiation.** You implement it or use an anonymous class — you never `new` an interface directly.
- **`static` interface methods aren't inherited** by implementers; call them on the interface name only.
- **Pick by relationship:** interface = "can-do" capability across unrelated types; abstract class = "is-a" with shared code. Default to **interface** for a pure contract to keep multiple-inheritance open.
- **C++ contrast:** no `interface` keyword — emulate with a class of **pure virtual** methods (`= 0`).
