# Encapsulation (Data Hiding)

> **One-liner:** Bundle data + the methods that act on it into one class, hide the data (`private`), and expose controlled access through methods.

**Trigger phrase:** *"private fields + public getters/setters/validation → outside world touches data only through a controlled interface."*

---

## Core Idea
- **Bundling:** keep an object's fields and the methods that operate on them together in one class.
- **Hiding:** mark fields `private` so no external code can read/write them directly.
- **Controlled access:** expose `public` methods (getters/setters/business methods) that gatekeep every read and write — letting you add **validation** or **logic** in between.

> Encapsulation is the **principle** (hide internal state). `private` + getters/setters are the **mechanism** that achieves it. → leads into [[2. Access Modifiers]].

## Why it matters (4 wins)
| Benefit | What it buys you |
|---|---|
| **Data security** | State can't be changed arbitrarily from outside — only via validated methods. |
| **Flexibility / maintenance** | Change the internal representation freely as long as the public method signatures stay the same. |
| **Modularity** | Related data + behavior live together → cleaner, more readable code. |
| **Easier debug/test** | All state changes funnel through a few methods → one place to validate and trace. |

## Minimal Example
```java
class BankAccount {
    private String holder;     // hidden state
    private double balance;

    public BankAccount(String holder, double balance) {
        this.holder = holder;
        this.balance = balance;
    }

    public double getBalance() { return balance; }   // controlled read

    public void deposit(double amt) {                // validated write
        if (amt > 0) balance += amt;
        else System.out.println("Deposit must be positive.");
    }

    public void withdraw(double amt) {
        if (amt > balance) System.out.println("Insufficient funds.");
        else balance -= amt;
    }
}
```
`balance` can never be set to a junk value from outside — `deposit`/`withdraw` enforce the rules.

## Key Takeaways
1. **Private data** → no direct external access.
2. **Public methods** → the only doorway in/out, where validation lives.
3. **Principle vs mechanism** → encapsulation is *the goal*; access modifiers + getters/setters are *how*.

## Pitfalls
- **Getter/setter on everything ≠ encapsulation.** A blind public setter for every private field just re-exposes the state — add real validation/logic or expose intent-revealing methods (`deposit`) instead of `setBalance`.
- Don't confuse it with **abstraction**: abstraction hides *complexity/implementation* (the "what vs how"); encapsulation hides *data* and bundles it with behavior.
