# Abstraction

> **One-liner:** Hide the *how*, show only the *what* — expose a clean interface, conceal the implementation. (Driving a car: you use the steering wheel, not the engine internals.)

**Trigger phrase:** *"focus on what an object does, not how — declare a contract via `abstract class` or `interface`, leave the implementation to subclasses."*

---

## Core Idea
Show only the **necessary interface**, hide the implementation details. Two tools in Java: **abstract classes** and **interfaces**.

> **Abstraction vs Encapsulation:** abstraction hides *complexity / implementation* (design level — "what vs how"); [[1. Encapsulation]] hides *data* (bundles it behind getters/setters). Often work together.

## Method vocabulary
- **Abstract method** — declared, **no body**; subclass *must* implement it.
- **Concrete method** — full implementation; inherited (and overridable).

## Tool 1 — Abstract Class
Cannot be instantiated; meant to be extended. Can mix **abstract + concrete** methods.
```java
abstract class Animal {
    void eat() { System.out.println("This animal eats food."); } // concrete
    abstract void sound();                                        // abstract — no body
}
class Dog extends Animal { @Override void sound(){ System.out.println("barks"); } }
class Cat extends Animal { @Override void sound(){ System.out.println("meows"); } }
```
Each subclass inherits `eat()`, **must** implement `sound()`.

## Tool 2 — Interface
A pure **contract**. All methods implicitly `public abstract` (pre-Java 8); a class `implements` it and fulfills every method.
```java
interface Animal { void sound(); void eat(); }   // all abstract
class Dog implements Animal {
    @Override public void sound(){ System.out.println("barks"); }
    @Override public void eat()  { System.out.println("eats food"); }
}
```

## Abstract Class vs Interface
| | **Abstract Class** | **Interface** |
|---|---|---|
| Methods | abstract **+** concrete | abstract (+ `default`/`static` since Java 8) |
| Fields | instance fields allowed | `public static final` constants only |
| Inheritance | single (`extends` one) | **multiple** (`implements` many) → dodges Diamond |
| Constructor | **yes** (called via subclass `super()`) | no |
| Use when | shared base + shared code | pure capability/contract across unrelated classes |

## Interface extras (Java 8+)
- **`static` method** — belongs to the *class/interface*, called without an instance (`Example.staticMethod()`); can only touch other static members.
- **`default` method** — has a body in the interface (`default` keyword). **Why added:** let interfaces gain new methods **without breaking existing implementers** (backward compatibility); also resolves clashes when implementing multiple interfaces. Implementers may override it.

## Interview Q&A (memorize)
1. **Can an abstract class extend another abstract class?** ✔️ Yes — child inherits the abstracts; if it doesn't implement them all, it must itself be `abstract`.
2. **Can an abstract class have a constructor / be instantiated?** Constructor **yes**, instantiation **no**. The constructor runs when a *subclass* is created (via `super()`) to init inherited fields.

## Pitfalls
- **Abstraction ≠ encapsulation.** Design-level hiding (what/how) vs data-level hiding. Common interview mix-up.
- **Interface fields are constants.** Anything declared is silently `public static final` — not instance state.
- **Pick by relationship:** abstract class = "is-a" with shared code; interface = "can-do" capability across unrelated types. Default to **interface** when you only need a contract (keeps multiple-inheritance open).
- **C++ contrast:** no `interface` keyword — you emulate it with a class of **pure virtual** methods (`= 0`); abstraction there leans on `virtual`.
