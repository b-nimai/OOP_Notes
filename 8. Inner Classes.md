# Inner Classes

> **One-liner:** A class defined **inside another class** — logically groups a helper that's only used in one place, and gets direct access to the outer class's members (even `private`).

**Trigger phrase:** *"a class inside a class — 4 flavors (static nested / non-static inner / local / anonymous); static nested needs no outer instance, the rest do."*

---

## Core Idea
An inner class lives **inside** an outer class. Use it to keep a helper close to where it's used → more readable, more encapsulated. Depending on the flavor it can reach the outer class's members directly, including `private` ones.

**The 4 flavors at a glance:**

| Flavor | Declared | Needs outer instance? | Can access |
|--------|----------|------------------------|------------|
| **Static nested** | `static class` inside class | ❌ No | only **static** members of outer |
| **Non-static inner** | `class` inside class (no `static`) | ✅ Yes (`outer.new Inner()`) | **all** members of outer (incl. `private`) |
| **Local** | `class` inside a method/block | (lives in the method) | all outer members **+ effectively-final** locals |
| **Anonymous** | unnamed, at point of use | (same as local) | all outer members + effectively-final locals |

> **Memory hook:** only the **static** one is independent; the other three all cling to an outer instance / enclosing scope.

---

## 1. Static Nested Class
Marked `static` → **no outer instance needed**. Can touch only the **static** members of the outer class. Use it to group a tightly-related helper that needs no instance data.
```java
class OuterClass {
    static int staticVar = 100;

    static class StaticNestedClass {        // static → independent
        void display() {
            System.out.println("Static variable: " + staticVar);
        }
    }
}

class Main {
    public static void main(String[] args) {
        // no OuterClass object required:
        OuterClass.StaticNestedClass obj = new OuterClass.StaticNestedClass();
        obj.display();                       // Static variable: 100
    }
}
```
**Keypoints**
- Declared with `static`; **no reference** to an outer instance is kept.
- Can access **only static** members of the outer class.
- Instantiate via `OuterClass.StaticNestedClass` — no outer object.

**Real-world:** `Map.Entry` is a static nested class inside `Map` — a key/value pair that belongs conceptually to `Map` but needs no `Map` instance.

## 2. Non-Static Inner Class
No `static` → **tied to an outer instance**. Can access **all** members of the outer class, including `private`. Created through an existing outer object with the odd `outer.new Inner()` syntax.
```java
class OuterClass {
    int instanceVar = 42;                    // instance (non-static) field

    class InnerClass {                        // non-static → tied to an outer object
        void display() {
            System.out.println("Instance variable: " + instanceVar);
        }
    }
}

class Main {
    public static void main(String[] args) {
        OuterClass outer = new OuterClass();
        OuterClass.InnerClass inner = outer.new InnerClass();  // note: outer.new
        inner.display();                     // Instance variable: 42
    }
}
```
**Keypoints**
- Declared **without** `static`; each inner object holds a hidden reference to its outer object.
- Needs an outer instance first → `outer.new InnerClass()`.
- Can access **all** outer members (static + instance + `private`).

## 3. Local Inner Class
Defined **inside a method or block**; visible only within that scope. Can use outer members **and** the enclosing method's **effectively-final** local variables.
```java
class OuterClass {
    void outerMethod() {
        int localVar = 10;                   // effectively final (never reassigned)

        class LocalInnerClass {              // class declared inside a method
            void display() {
                System.out.println("Local variable: " + localVar);
            }
        }

        new LocalInnerClass().display();     // Local variable: 10
    }
}
```
**Keypoints**
- Defined within a method/block; **scoped** to it.
- Sees all outer members **+** effectively-final locals only.

> **Why "effectively final"?** The inner object can outlive the method call, but the local variable dies when the method returns. Java copies the value into the inner class, so the variable must never change — otherwise the copy and the original could disagree.

## 4. Anonymous Inner Class
A **local inner class with no name**, declared and instantiated in one shot. Perfect for a **one-time** implementation of an interface or subclass of an abstract class.
```java
abstract class Greeting {
    abstract void sayHello();
}

class Main {
    public static void main(String[] args) {
        Greeting greeting = new Greeting() {     // subclass made & instantiated inline
            void sayHello() {
                System.out.println("Hello, World!");
            }
        };
        greeting.sayHello();                     // Hello, World!
    }
}
```
**Keypoints**
- **No name**; created exactly where it's declared.
- Used when a class is needed **only once**.
- Classic uses: event listeners, `Runnable`, `Comparator` — though Java 8 **lambdas** now replace anonymous classes that implement a single-method (functional) interface.
```java
// Anonymous class vs the modern lambda for a one-method interface:
Runnable r1 = new Runnable() {           // anonymous inner class
    public void run() { System.out.println("run"); }
};
Runnable r2 = () -> System.out.println("run");   // lambda — same thing, shorter
```

## When to use which (decision hint)
- Helper needs **no** outer instance data → **static nested**.
- Helper needs the outer object's **instance** data → **non-static inner**.
- Helper used **only inside one method** → **local inner**.
- **One-off** implementation of an interface/abstract class → **anonymous** (or a **lambda** if it's a single-method interface).

## Interview Q&A (memorize)
1. **Static nested vs inner class?** Static nested needs **no outer instance** and sees only static members; a (non-static) inner class is **tied to an outer object** and sees everything.
2. **Why must captured locals be effectively final?** The inner object can outlive the method, so Java **copies** the local's value — it must not change, or copy and original would diverge.
3. **How do you instantiate a non-static inner class?** Through an outer object: `outer.new InnerClass()`.
4. **Lambda vs anonymous inner class?** A lambda is shorthand for an anonymous class **implementing a single-method (functional) interface**; it has no `this`-of-its-own and is more concise.

## Pitfalls
- **Wrong instantiation syntax.** Non-static inner → `outer.new InnerClass()`, **not** `new OuterClass.InnerClass()` (that form is for **static** nested only).
- **Static nested can't touch instance members.** Like any static context, it sees only static outer members.
- **Non-static inner holds a hidden outer reference** → can cause **memory leaks** (e.g. an inner class outliving its outer in Android/listeners). Prefer `static` nested when you don't need outer instance data.
- **Capturing a mutable local fails to compile.** Reassigning a captured local breaks "effectively final."
- **Inner ≠ nested terminology.** "Nested" = any class inside another; "inner" specifically means the **non-static** kind.
