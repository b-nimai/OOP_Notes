# Object Cloning

> **One-liner:** Make an independent copy of an object (same data, new memory address) — **shallow** copies share nested objects, **deep** copies duplicate them too.

**Trigger phrase:** *"copy an object: implement `Cloneable`, override `clone()`. Default `super.clone()` = shallow (nested refs shared); deep clone = also clone every nested object yourself."*

---

## Core Idea
Cloning creates a duplicate object with the same structure and field values but at a **new memory location**. In Java it's wired through the **`Cloneable`** marker interface + the **`Object.clone()`** method. The catch is *how deep the copy goes* — primitives are always copied, but **reference fields** may be shared (shallow) or duplicated (deep).

**Why clone instead of re-building?**
- **Efficiency** — duplicate in one call vs reconstruct + reinitialize from scratch.
- **Reduce coupling** — changes to the copy don't leak into the original.
- **Preserve state** — snapshots for **undo/redo**, caching, rollback.
- **Modifiable copies** of otherwise immutable/locked objects.
- **Prototype pattern** — replicate a pre-configured object instead of `new` + setup.

## The two moving parts
1. **`Cloneable`** — a **marker interface** (no methods). It just flags to the JVM that calling `clone()` on this class is legal. Forget it → `clone()` throws **`CloneNotSupportedException`**.
2. **`Object.clone()`** — inherited from `Object`, `protected`, so you **override** it to expose/customize cloning. By default it does a **shallow copy**: allocates new memory, copies each field's value (for references, copies the *reference*, not the pointed-to object).

---

## Shallow Cloning (the default)
`super.clone()` copies fields at the surface: primitives/Strings copied, but **reference fields point to the same nested objects**. So the clone is a separate object, yet it **shares** its nested objects with the original — mutate one, both see it.
```java
class Address {
    String city;
    Address(String city) { this.city = city; }
}

class Person implements Cloneable {          // must implement Cloneable
    String name;
    Address address;                         // reference-type field — will be SHARED
    Person(String name, Address address) { this.name = name; this.address = address; }

    @Override
    protected Object clone() throws CloneNotSupportedException {
        return super.clone();                // shallow copy
    }
}

class Main {
    public static void main(String[] args) throws CloneNotSupportedException {
        Person person = new Person("Rahul", new Address("Mumbai"));
        Person clone  = (Person) person.clone();

        clone.address.city = "New Delhi";    // mutate the SHARED Address

        System.out.println(person.address.city);  // New Delhi  ← original changed too!
        System.out.println(clone.address.city);   // New Delhi
    }
}
```
**Why both change:** `person.address` and `clone.address` are two references to the **same** `Address` object. That's the key limitation of shallow cloning.

## Deep Cloning (manual)
A fully independent copy — every nested object is cloned too, so the two trees share nothing. Since `super.clone()` only goes one level, you **clone the nested objects yourself**.
```java
class Address implements Cloneable {
    String city;
    Address(String city) { this.city = city; }

    @Override
    protected Object clone() throws CloneNotSupportedException {
        return new Address(this.city);       // make a brand-new Address
    }
}

class Person implements Cloneable {
    String name;
    Address address;
    Person(String name, Address address) { this.name = name; this.address = address; }

    @Override
    protected Object clone() throws CloneNotSupportedException {
        Person cloned = (Person) super.clone();      // shallow copy first
        cloned.address = (Address) address.clone();  // then deep-copy the nested object
        return cloned;
    }
}

class Main {
    public static void main(String[] args) throws CloneNotSupportedException {
        Person person = new Person("Rahul", new Address("Mumbai"));
        Person clone  = (Person) person.clone();

        clone.address.city = "New Delhi";    // mutate the clone's OWN Address

        System.out.println(person.address.city);  // Mumbai     ← original safe
        System.out.println(clone.address.city);   // New Delhi
    }
}
```
**Why `Address` must override `clone()`:** without it, `address.clone()` wouldn't be callable/usable — and each `Person` would otherwise share one `Address`. Deep cloning = "clone the whole object graph, level by level."

---

## Shallow vs Deep — at a glance
| Aspect | Shallow | Deep |
|--------|---------|------|
| Copies primitive/`String` fields | ✅ | ✅ |
| Copies object references | shares the **same** nested object | duplicates into a **new** nested object |
| Override `clone()` in nested classes? | ❌ not needed | ✅ required |
| Nested objects independent? | ❌ shared | ✅ independent |
| When to use | object has **only primitives** (or immutable fields) | object holds refs to **mutable** objects |

> **Memory hook:** **Shallow = share, Deep = duplicate.** If all fields are primitives/immutables, shallow already behaves like deep.

## Other ways to deep-copy (good to mention)
- **Copy constructor** — `new Person(other)` that re-builds nested objects by hand (often cleaner than `Cloneable`).
- **Serialization round-trip** — serialize then deserialize the object graph (deep copy "for free", but slower; needs `Serializable`).
- These avoid the well-known awkwardness of `Cloneable`/`clone()`.

## Interview Q&A (memorize)
1. **Is `Cloneable` a real interface with methods?** No — it's a **marker** interface; it just permits `clone()`. The actual method lives in `Object`.
2. **Why does `clone()` throw `CloneNotSupportedException`?** Java forbids cloning classes that didn't opt in via `Cloneable`, preventing accidental cloning.
3. **Shallow vs deep in one line?** Shallow shares nested objects; deep duplicates them so the copies are fully independent.
4. **How to deep-clone?** Override `clone()` and clone each nested object (recursively), or use a copy constructor / serialization.

## Pitfalls
- **Shallow clone's shared references** are the #1 trap — mutating a nested object on the clone mutates the original (the `New Delhi` effect).
- **Forgetting `implements Cloneable`** → `CloneNotSupportedException` at runtime, not compile time.
- **`clone()` is `protected`** and the design is widely considered flawed (Joshua Bloch: *"prefer a copy constructor or copy factory"*) — know it for interviews, prefer copy constructors in practice.
- **`clone()` bypasses constructors** — no constructor logic/validation runs on the copy.
- **Deep clone needs every level to cooperate** — one nested class that doesn't deep-copy leaves a shared reference hiding in the graph.
