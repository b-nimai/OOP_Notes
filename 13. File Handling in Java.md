# File Handling in Java

> **One-liner:** Read from and write to files on disk for **persistent** storage — `File` represents the path, streams/readers/writers move the bytes/chars, `try-with-resources` guarantees they're closed.

**Trigger phrase:** *"`File` = the path handle (create/exists/delete/length); `FileWriter`+`BufferedWriter` to write, `FileReader`+`BufferedReader` to read line-by-line; wrap in `try-with-resources` so streams auto-close; `new FileWriter(path, true)` = append mode."*

---

## Core Idea
A program's variables live in RAM and vanish when it exits. **File handling** writes data to disk so it **survives** between runs (persistence). Java's `java.io` package models this: a **`File`** object names a path, and **streams/readers/writers** carry data in and out. Every operation can fail (missing file, no permission, disk full) → file code is wrapped in `try-catch` for `IOException`.

**Core operations:** create · read · write · append · delete.

**Why it matters (in OOP apps):** **logging** (debug/monitor) · **configuration** (read/write settings) · **data storage** (user content, records, backups).

> **Mental model:** `File` is the *address* of a house; readers/writers are the *trucks* that move stuff in and out; `try-with-resources` is the driver who **always** shuts the door.

---

## The `File` class — the path handle
From `java.io`. A `File` object represents a path (file **or** directory); creating one does **not** create a file on disk — you call methods for that.

| Method | Does |
|--------|------|
| `createNewFile()` | creates an empty file → `true` if new, `false` if it already existed (throws `IOException`) |
| `exists()` | does this path exist? |
| `delete()` | delete the file/empty dir |
| `getName()` / `getAbsolutePath()` | file name / full path |
| `length()` | size in **bytes** |
| `canRead()` / `canWrite()` | permission checks |

```java
File file = new File("example.txt");
try {
    if (file.createNewFile()) System.out.println("File created: " + file.getName());
    else                      System.out.println("File already exists.");
} catch (IOException e) { e.printStackTrace(); }   // permissions / bad path / disk issue
```
Inspecting properties:
```java
if (file.exists()) {
    System.out.println(file.getAbsolutePath() + " | " + file.length() + " bytes"
        + " | writable=" + file.canWrite() + " readable=" + file.canRead());
}
```

## Writing — `FileWriter` + `BufferedWriter`
- **`FileWriter`** writes **characters** to a file.
- **`BufferedWriter`** wraps it and buffers data in memory, flushing in big chunks → **far fewer disk hits, much faster**. Same idea for read side.

```java
try (BufferedWriter writer = new BufferedWriter(new FileWriter("output.txt"))) {
    writer.write("Hello, world!\n");
    writer.write("This is a sample file.");
}   // auto-closed (which also flushes the buffer)
catch (IOException e) { e.printStackTrace(); }
```
- **Append vs overwrite:** `new FileWriter("f.txt")` **overwrites**; `new FileWriter("f.txt", true)` **appends** (the `true` flag) — crucial for logs.
- Always **close** (or use try-with-resources) — buffered data not flushed = **lost writes**.

## Reading — `FileReader` + `BufferedReader`
- **`FileReader`** reads characters; **`BufferedReader`** adds buffering **and** the handy **`readLine()`** (reads a whole line, returns `null` at end of file).
```java
try (BufferedReader reader = new BufferedReader(new FileReader("example.txt"))) {
    String line;
    while ((line = reader.readLine()) != null)   // null ⇒ end of file
        System.out.println(line);
}
catch (IOException e) { e.printStackTrace(); }
```

---

## try-with-resources — the right way to close
A `try` with the resource **declared in its parentheses**. Any resource that implements **`AutoCloseable`** (all streams/readers/writers do) is **closed automatically** when the block ends — even on exception or `return`. Eliminates leaks and the boilerplate `finally { reader.close(); }`.
```java
try (BufferedReader r = new BufferedReader(new FileReader("example.txt"))) {
    // use r...
}   // r.close() called automatically
catch (IOException e) { e.printStackTrace(); }
```
> **Old way (avoid):** declare the reader outside, close it in `finally` — verbose and easy to forget. Prefer try-with-resources always.

## Putting it together — a Logger
Real use of append-mode writing: a `Logger` that creates the file once, then appends each message.
```java
class Logger {
    private String path;
    Logger(String path) throws IOException {
        File file = new File(path);
        if (!file.exists()) file.createNewFile();   // create once
        this.path = path;
    }
    public void log(String message) {
        try (BufferedWriter bw = new BufferedWriter(new FileWriter(path, true))) { // true = APPEND
            bw.write(message);
            bw.newLine();                           // platform-correct line break
        } catch (Exception e) {
            System.out.println("Failed to log: " + message);
        }
    }
}
// myLogger.log("Application started...");  → each call appends a line, nothing overwritten
```
- The `true` in `FileWriter(path, true)` is what makes successive `log()` calls **accumulate** instead of overwrite.
- For production, prefer the built-in **`java.util.logging`** package (timestamps, levels, handlers) over rolling your own.

## Interview Q&A (memorize)
1. **`FileWriter` vs `BufferedWriter`?** `FileWriter` writes chars straight to disk; `BufferedWriter` wraps it and buffers → fewer disk writes, faster (+ `newLine()`).
2. **How to read a file line by line?** `BufferedReader.readLine()` in a `while` loop until it returns `null`.
3. **Overwrite vs append?** `new FileWriter(path)` overwrites; `new FileWriter(path, true)` appends.
4. **Why try-with-resources?** Auto-closes `AutoCloseable` resources → no leaks, no manual `finally`, flushes buffers.
5. **What exceptions?** `FileNotFoundException` (missing file — subclass of `IOException`) and `IOException` (permissions, disk, network).
6. **Does `new File("x.txt")` create a file?** No — it's just a path object; call `createNewFile()` (or write to it) to actually create it.

## Pitfalls
- **Forgetting to close** a writer → buffered data never flushed = **lost data**; use try-with-resources.
- **Resource leaks** — closing inside `try` (not `finally`/try-with-resources) skips cleanup when an exception hits.
- **Overwrite surprise** — default `FileWriter` truncates the file; pass `true` to append.
- **Assuming the file exists** — guard reads with `exists()` or catch `FileNotFoundException`.
- **`File` object ≠ real file** — constructing one doesn't touch the disk.
- **Char vs byte streams** — `Reader`/`Writer` are for **text**; for images/binary use `InputStream`/`OutputStream` (e.g. `FileInputStream`).
